# Agent Harness Project

Репозиторий для разработки общего agent harness. Версионный Windows-пакет собирается из `distribution/windows/`. Оригиналы источников и полный структурированный разбор хранятся отдельно от пакета.

## Текущий статус

- Версия исходников пакета — кандидат 0.4.2. Общий каталог `%USERPROFILE%\.agents` предназначен для правил, навыков, нейтральных выжимок и курируемой памяти. Установка в реальный профиль не подтверждена проверками этого репозитория.
- Навыки: `document-ingest` разбирает документ в выбранный каталог; `source-to-knowledge` помогает получить выжимку или идею; `memory-maintenance` обслуживает одобренные записи памяти.
- Личная библиотека источников — отдельный проект для оригиналов, полного текста и индекса. Она не входит в ZIP.
- Пакет распространяется как версионный ZIP; обновления принимаются вручную. Git remote и опубликованный выпуск пока не созданы.

## Содержимое репозитория

| Путь | Назначение |
| --- | --- |
| `distribution/windows/` | Исходники пакета, [описание](distribution/windows/readme.md) и [инструкция](distribution/windows/installation-guide.md). |
| `tests/` | Проверки установщика и обработки документов. |
| `tools/` | Сборщик ZIP. |
| `CHANGELOG.md` | Изменения кандидата и порядок версионирования. |

Локальные исходные и рабочие материалы, правила проекта и сторонний навык интервьюирования исключены из Git. Не добавляйте секреты или клиентские данные. Перед публикацией проверьте содержимое репозитория и права на распространение. Коллегам можно передавать отдельно собранный и проверенный `agent-harness-windows-vX.Y.Z.zip`.

## Разработка

Сборка: `tools/build-windows-release.ps1 -OutputDirectory <пустой каталог>`. Запускайте `install.cmd` только из полностью распакованного ZIP: `manifest.json` создаётся при сборке и отсутствует в исходной папке. Проверки находятся в `tests/windows/` и `tests/ingest/`. Состав пакета задан в сборщике.

Версия пакета хранится в `distribution/windows/version.txt`; сборщик добавляет её в имя ZIP и манифест. Git-коммиты фиксируют изменения между отправками, а теги `vX.Y.Z` предназначены для проверенных выпусков. Порядок подготовки выпуска описан в `CHANGELOG.md`.
