# shared-agent-harness

**Shared Agent Harness** — общая файловая среда для работы с ИИ-агентами. Она помогает использовать одни и те же правила, навыки и выбранные знания в Codex, Claude Code и OpenCode, вместо того чтобы вручную поддерживать отдельную копию для каждого приложения.

Пакет предназначен для личной работы на Windows. Он подключается к уже установленным приложениям, но не устанавливает их и не обновляет. Знания и память на старте представлены пустыми шаблонами: вы сами решаете, чем их наполнять.

## Как это работает

1. Установщик создаёт общий каталог `%USERPROFILE%\.agents` и предлагает выбрать приложения из обнаруженных на компьютере.
2. Он подключает выбранные приложения к общим правилам и навыкам. В новых сеансах агент получает инструкции читать правила из общего каталога; если приложение не обнаружило навык автоматически, правила указывают агенту открыть его файл вручную.
3. При содержательной задаче агент проверяет индекс знаний и сведения о темах в памяти, выбирает подходящие записи и использует их как контекст. Он должен отделять информацию источника, ваши идеи и проверенный опыт.
4. Прежде чем добавить или изменить запись общей памяти, агент показывает точный текст и ждёт вашего одобрения. Личные правила согласовываются отдельно.

Материалы хранятся в обычных локальных файлах. Работа с клиентскими данными остаётся в конкретном разрешённом проекте; секреты и клиентские материалы не предназначены для общей памяти. Отдельная резервная копия общих файлов не создаётся автоматически.

## Что хранится в общей среде

| Раздел | Назначение |
| --- | --- |
| `knowledge/` | Нейтральные выжимки из книг, статей и других источников с указанием происхождения. |
| `memory/profile.md`, `company.md`, `decisions.md` | Подтверждённый контекст о владельце и компании и межпроектные решения. |
| `memory/ideas/` и `memory/records/` | Идеи для дальнейшего анализа и отдельно — выводы с проверенным результатом и условиями применения. |
| `rules/personal.md` | Отдельно одобренные правила поведения агента. |
| `history/` | Предыдущие версии, устаревшие и опровергнутые записи; каталог создаётся по мере работы. |

Оригиналы документов и полный текст их разбора хранятся в выбранном вами отдельном месте. Пакет не создаёт личную библиотеку источников и не включает её содержимое.

## Навыки в пакете

| Навык | Для чего нужен |
| --- | --- |
| `document-ingest` | Разбирает DOCX, PDF или FB2 в выбранный каталог: извлекает текст и изображения, создаёт индекс и отмечает пробелы. |
| `source-to-knowledge` | Помогает подготовить нейтральную выжимку или личную идею из разрешённого источника; при необходимости использует `document-ingest`. |
| `memory-maintenance` | Помогает найти подходящие записи памяти или предложить их создание, изменение и архивирование с вашим одобрением. |

Навыки можно вызвать обычной просьбой в чате, например:

> Помоги составить мой профиль для общей памяти. Покажи точный текст и дождись моего одобрения.

> Разбери этот документ в указанной папке и предложи нейтральную выжимку. Покажи пропуски извлечения и ничего не сохраняй в общую память без моего одобрения.

Подробнее о наполнении памяти и примерах запросов — в [описании пакета](distribution/windows/readme.md).

## Текущий статус

- Версия исходников пакета — 0.4.3. Общий каталог `%USERPROFILE%\.agents` предназначен для правил, навыков, нейтральных выжимок и курируемой памяти. Установка в реальный профиль не подтверждена проверками этого репозитория.
- Навыки: `document-ingest` разбирает документ в выбранный каталог; `source-to-knowledge` помогает получить выжимку или идею; `memory-maintenance` обслуживает одобренные записи памяти.
- Личная библиотека источников — отдельный проект для оригиналов, полного текста и индекса. Она не входит в ZIP.
- Пакет распространяется как версионный ZIP; обновления принимаются вручную.
- Проверены сборка, целостность пакета и сценарии установки во временных профилях. Автоматическое обнаружение навыков во всех реальных приложениях и OCR сканированных PDF пока не подтверждены; WSL в текущий пакет не входит.

## Установка

1. Скачайте готовый ZIP и файл SHA-256 со [страницы выпусков](https://github.com/snn02/shared-agent-harness/releases), проверьте контрольную сумму и полностью распакуйте архив в отдельную папку.
2. Запустите `install.cmd` двойным щелчком. Установщик проверит состав пакета и предложит выбрать обнаруженные приложения.
3. Просмотрите изменения, подтвердите установку и проверьте результат в новом сеансе приложения.

Пошаговое описание и действия при конфликтах — в [инструкции по установке](distribution/windows/installation-guide.md). Для разбора документов могут понадобиться Python 3.12 и зависимости, указанные в навыке. Скачивайте готовый ZIP из выпуска: автоматически сформированный GitHub архив исходников не содержит манифест установщика.

При обновлении скачайте новый ZIP, распакуйте его в другую папку и снова запустите установщик. Он показывает изменения до записи и сохраняет локальные правки при конфликтах для ручного сравнения; автоматического обновления нет.

## Разработка

Сборка в PowerShell: `./tools/build-windows-release.ps1 -OutputDirectory ./dist/release -ExpectedVersion 0.4.3`; выберите пустой каталог результата. Запускайте `install.cmd` только из полностью распакованного ZIP: `manifest.json` создаётся при сборке и отсутствует в исходной папке. Состав пакета задан в сборщике.

Проверки находятся в `tests/windows/` и `tests/ingest/`. Windows-тесты используют каталог `dist/test-scratch`, который нужно создать перед запуском. Для Python-тестов нужны Python 3.12, зависимости из `distribution/windows/payload/skills/document-ingest/scripts/requirements.txt` и дополнительная тестовая зависимость PyMuPDF. Чтобы запуск Python-тестов не оставлял `__pycache__` в исходниках пакета, задайте в PowerShell `$env:PYTHONDONTWRITEBYTECODE = '1'` и выполните `python -m unittest discover -s tests/ingest -v`. Сборщик отклоняет посторонние файлы в исходной папке пакета.

Версия пакета хранится в `distribution/windows/version.txt`; сборщик добавляет её в имя ZIP и манифест. Git-коммиты фиксируют изменения между отправками, а теги `vX.Y.Z` предназначены для проверенных выпусков. Порядок подготовки выпуска описан в `CHANGELOG.md`.
